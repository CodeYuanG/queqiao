# 排查远程电脑

由**鹊桥（Queqiao）**提供远程协助能力：让 Agent 帮你排查另一台电脑。

本技能是使用说明，不是远程控制程序。安装技能不会获得任何远程权限，也不能代替下面两个程序：

- **协助方本机：MCP 控制端**（`RemoteAssist.Mcp` / `RemoteAssist.Mcp.exe`）。由当前这个 Agent 在本机通过 stdio 调用。
- **被协助电脑：鹊桥桌面端**。必须由对方在那台电脑上自己安装、打开，并主动分享连接凭证。

官方网站 `http://121.196.45.81/` 提供下载和中继接入，**不是**可直接填写到 MCP 配置里的托管 MCP 地址。不要把该网址当成 `--transport http` 的远程 MCP。

## 何时使用

- 用户希望用当前 Agent 查看另一台电脑的进程、服务、目录、文本文件或日志。
- 用户要在本机安装或检查鹊桥 MCP 控制端。
- 用户已经拿到对方分享的连接凭证，准备连接并排障。

不要在用户只是问「鹊桥是什么」且没有安装或排障意图时，主动下载程序或改配置。

## 安全规则（必须遵守）

1. **先征得用户明确授权**，再下载控制端、访问网络、或改写 MCP 配置。不要默认执行。不要用 `curl | sh`、`iwr | iex` 这类管道盲执行。
2. **当前公开下载地址是 HTTP**（不是 HTTPS）。下载前向用户说明来源，并只使用官方说明里的地址；不要改去网盘、第三方镜像或来路不明的 GitHub Release。
3. **不要编造、猜测、上传或记录连接凭证。** 凭证必须由被协助者主动分享。不要把凭证写进日志、提交到 git、发给第三方服务，或写进 MCP 配置里的 `REMOTE_ASSIST_PAYLOAD`。
4. **安装阶段不要调用 `connect`，不要连接远端，也不要执行远端命令。** 即便已经能启动控制端，也等到用户另行提供凭证后再连接。
5. **不要绕过本机审批。** 技能和 MCP 都没有远程提权入口。拒绝或超时后不要反复重试刷屏。
6. 这台协助用的电脑不要安装鹊桥桌面版来「凑合」当控制端。对方那台电脑的桌面版，把下载地址发给对方自己安装。

更细的安装步骤见 [references/install.md](references/install.md)；工具与权限差异见 [references/tools.md](references/tools.md)。若本技能记录的文件名与当时官网 `/agent.md` 或下载页不一致，**下载地址以当时官网为准**，但上述安全规则仍以本技能为准。

## 两种凭证，权限不同

用户应粘贴「复制连接凭证」得到的**完整** `remoteassist:pair?...` 载荷（含 `fp=`）。不要只让对方口述不完整的短码，就宣称已经安全连接。

| 类型 | 对方怎么开 | 连上时 | 执行命令 / 截屏 |
|------|------------|--------|-----------------|
| 临时协助码 | 当场点「开启接受协助」，并把完整凭证发给你 | 被协助者还要在本机点「允许协助」 | 默认还要再点允许或拒绝。拒绝或超时则没有改动 |
| 长久码（无人值守） | 对方在本机开启无人值守，并已确认风险 | **不弹**配对确认窗 | **不再逐次弹窗**，操作仍记在那台电脑上。不能说「全部操作都会审批」 |

另外，临时码会话里，对方若把本机信任等级改成「完全信任」，当前这次会话的改动也可能不再询问；这只能由对方在本机更改，不能远程打开。不要把「完全信任」或长久码说成默认行为。

## 标准排查流程

1. 若本机还没有可用的 MCP 控制端，先按 [references/install.md](references/install.md) 安装并完成验收；仍不要连接。
2. 请用户向被协助者要完整连接凭证。对方需要：打开鹊桥桌面端 → 开启接受协助或已启用长久码 → 复制整段凭证。
3. 用 `connection_status` 查看是否已连接。未连接时，只用用户刚提供的凭证调用 `connect`。已连接到别的会话时，先征得用户同意，再 `disconnect` 后连接新会话。
4. 连接成功后，先做只读排查：`host_info`、`list_processes`、必要时 `list_services`、`list_dir`、`read_log_tail`、`read_file`。按远端返回的 `path_style` 和 `shell` 选择路径与命令语法。
5. 用中文向用户说明发现和建议。需要看对方当前屏幕时，再使用 `take_screenshot`；在临时码且非完全信任时，要等对方本机点允许。
6. 只有在用户同意改动后，才使用 `run_command`，并填写对人友好的 `summary`。高风险操作（删文件、关机、改权限等）必须先征询用户。临时码默认要等对方本机审批；长久码或完全信任下可能不再逐次询问，仍要把将执行的命令告诉用户。
7. 排障结束后，征得用户同意再 `disconnect`。不要把凭证留下来重复使用，除非用户明确要求连接同一份长久码。

## 做不到的事

- 远程桌面、键鼠操控。
- 在没有凭证、对方未打开桌面端、或对方拒绝时，假装已经连上或已经改好。
- 让 Agent 绕过被协助本机的审批。
- 把中继网站当成托管 MCP 来配置。
