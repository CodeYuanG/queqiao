# 鹊桥 MCP 工具与权限

以下工具名和参数来自本仓库当前的 `apps/queqiao-mcp` 实现。业务工具在未 `connect` 时会返回明确错误，不要假装成功。

中继只转发加密会话，不能代为执行命令，也不能跳过本机确认。

## 工具一览

| 工具 | 用途 | 主要参数 |
|------|------|----------|
| `connect` | 用用户提供的凭证配对远端 | 必填 `payload`（完整 `remoteassist:pair?...` 载荷；实现也接受短码）。可选 `relay`（`host:port`，缺省用环境变量 `REMOTE_ASSIST_RELAY` 或内置中继） |
| `disconnect` | 断开当前会话；未连接时也安全 | 无 |
| `connection_status` | 返回 `connected` 或 `disconnected` | 无 |
| `host_info` | 远端系统基础信息（os、版本、架构、路径风格、shell 等） | 无。`connect` 成功时通常已附带 |
| `list_processes` | 列出远端进程 | 无 |
| `list_services` | 列出远端 Windows 服务及状态 | 无 |
| `list_dir` | 列远端目录 | 必填 `path`（远端绝对路径） |
| `read_file` | 读远端文本文件全文；大文件改用 `read_log_tail` | 必填 `path` |
| `read_log_tail` | 读日志末尾 | 必填 `path`；可选 `lines`，默认约 80 |
| `take_screenshot` | 截取远端主屏，经中继回传 JPEG | 无。临时码且非完全信任时，对方本机需点允许 |
| `run_command` | 向远端提议执行一条命令 | 必填 `command`；建议同时给 `summary`（显示在对方确认窗） |

路径按远端 `path_style` 填写：Windows 用盘符路径，posix 用 `/`。不要把协助方本机的路径发给这些工具。

## 调用时不要说错的权限

实现里的个别工具说明会写成「必须点允许才能执行」。更准确的产品规则是：

- **临时协助码**：连上要本机点「允许协助」。只读查看（进程、服务、目录、文本、日志）通过后即可进行。`run_command` 和 `take_screenshot` 默认还要本机点允许或拒绝；拒绝或超时则失败，没有改动。
- **对方在本机把信任等级改为「完全信任」**：仅对当前这次会话有效，写操作与截屏可能不再询问，但仍记在那台电脑上。不能远程打开此档。
- **长久码且已开启无人值守**：连上不弹配对窗，写操作和截屏也不再逐次弹窗，仍记审计。这是对方在本机二次确认风险后的结果，不能宣传成「所有操作都会审批」。
- **宽松档**：非高风险写操作可能不再询问，删除、关机、改权限等仍要问。默认不是这一档。

因此：不要承诺「每一次改动都会弹窗」；也不要在临时码默认场景里省略「需要对方点允许」。

## 连接凭证

- 推荐只使用用户粘贴的完整 `remoteassist:pair?...` 载荷，其中应包含业务证书指纹 `fp=`。
- 不要把凭证写入 MCP 配置或环境变量来「图方便」，除非用户明确要求启动即自动配对，并理解风险。
- 不要演示或编写真实可用的示例凭证。需要举例时，只写 `remoteassist:pair?...` 这种形式，不要填入 code、密码或指纹。
- 同一时间对方通常只接受一个协助端。换人、换会话时先 `disconnect` 再 `connect`。

## 明确不是托管 MCP

`REMOTE_ASSIST_RELAY` 的值是中继 `host:port`，例如公开默认 `121.196.45.81:17891`。这与网站 `http://121.196.45.81/` 不是同一类服务：

- 网站：介绍、下载、可选管理入口。
- 中继：协助双方经中继建立会话。
- MCP：始终是协助方本机上的 stdio 进程。

不要把网站或中继地址配成 `http` / `sse` MCP endpoint。
